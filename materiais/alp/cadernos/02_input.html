Como estudar este caderno

Leia as seções na ordem. Cada uma desenvolve uma ideia, mostra como ela aparece no código e explica o resultado. Os códigos curtos do texto são exemplos de leitura; o pacote ZIP reúne os programas completos e os exercícios para praticar depois.

Antes de executar um código, preveja o que será exibido. Compare a previsão com a explicação e observe qual instrução produz cada mudança. Não é necessário acertar de primeira: localizar a diferença faz parte do estudo.

No mundo físico

Uma pessoa faz a pergunta e espera outra responder antes de continuar. O convite e a resposta são falas diferentes; o programa também precisa esperar a confirmação da leitura.

1. O programa espera a participação do usuário

Um programa de atendimento pode precisar ouvir a resposta de quem o utiliza. input mostra uma mensagem de convite e espera uma linha digitada, concluída com Enter. A mensagem dentro dos parênteses é a pergunta do programa; a resposta vem do teclado. Não confunda esses dois textos ao prever a saída.

2. Pergunta, digitação e resultado têm origens diferentes

Ao executar um programa com input, três coisas podem aparecer no terminal: o convite escrito pelo programa, os caracteres digitados por você e uma saída posterior produzida por print. Ver tudo junto pode dar a impressão de que o programa imprimiu a resposta duas vezes. Na verdade, uma aparição pode ser apenas o eco normal da digitação no terminal.

Para interpretar corretamente a execução, identifique quem produziu cada parte. O texto entre aspas em input é o convite. O texto confirmado com Enter é a resposta. A chamada externa de print é responsável pela apresentação final da resposta recebida. Essa distinção evita confundir uma captura de terminal com a saída produzida apenas pelo código.

3. Uma chamada pode fornecer o valor para outra

Em print(input("Cidade: ")), a operação interna acontece primeiro. input solicita a cidade, aguarda a resposta e entrega o texto digitado. Só então print recebe esse texto e o exibe. Não é necessário compreender variáveis para observar essa sequência. Nesta etapa, o objetivo é receber e apresentar respostas, sem cálculos, conversões ou armazenamento.

4. A execução fica parada em um ponto específico

Enquanto a primeira leitura não recebe Enter, nenhuma instrução posterior deve ser considerada concluída. Você pode imaginar um marcador de execução esperando naquela linha. Só depois da confirmação ele segue. Em print(input(...)), o marcador resolve primeiro a chamada interna e depois a externa.

Isso explica por que não aparece tudo de uma vez quando existem várias perguntas. Uma chamada de input não lê o futuro nem preenche automaticamente outra chamada. Digitar uma resposta vazia também é uma resposta: pressionar Enter sem caracteres fornece um texto vazio. Neste tópico, não vamos validar esse conteúdo; estamos observando o mecanismo de leitura.

Python · exemplo explicado
print(input("Cidade: "))
print(input("Bairro: "))
Resultado
Roteiro: digite Contagem e confirme; depois digite Centro e confirme.
As chamadas de print exibem Contagem e Centro, nessa ordem.

Como ler a execução

A segunda pergunta só acontece depois de a primeira resposta ter sido recebida e exibida. As respostas não são armazenadas em variáveis neste exemplo.

5. Duas leituras são dois momentos distintos

Cada input recebe uma linha. Se houver duas chamadas, o programa espera duas confirmações com Enter. Digitar duas palavras em uma linha não responde automaticamente à segunda pergunta. Execute os exemplos usando respostas diferentes para identificar qual chamada produziu cada saída. Ao repetir o programa, as leituras começam novamente; ele não guarda as respostas da execução anterior.

6. Por que receber texto ainda não significa calcular

Se você digitar 24.90, input recebe os caracteres desse texto. O fato de a resposta parecer um número não muda automaticamente seu tipo. A mesma leitura também poderia receber Shampoo ou uma frase. Por isso, primeiro aprendemos a entrada como recepção de texto. No próximo tópico, uma variável permitirá reutilizar a resposta e uma conversão permitirá interpretá-la como número.

Não acrescente conversões sem entender a exigência do problema. Um código de produto pode ser um identificador textual, mesmo quando contém apenas algarismos. Por enquanto, a pergunta central é: qual texto o programa solicita e qual texto ele mostra? Manter esse foco torna visível a ordem das operações.
