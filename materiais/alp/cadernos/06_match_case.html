Percurso deste caderno #

Muitos menus de caixa, códigos de operação e siglas de setores da Lojas Blue dependem de comparar uma única variável contra uma lista de valores fixos conhecidos (como opção 1, 2, 3 ou 0). A partir do Python 3.10, a estrutura match / case permite expressar essa seleção por igualdade literal de maneira limpa e organizada.

Pré-requisito: Caderno 05 (Decisões com if, elif e else).

Conceito-chaveO que você vai dominar neste caderno
match expressao:Avalia uma única vez o valor de referência que será comparado.
case literal:Executa o bloco correspondente ao primeiro valor literal que coincidir.
Agrupamento com |Permite que dois ou mais literais compartilhem o mesmo bloco (ex.: case 'S' | 's':).
Padrão curinga (case _:)Captura qualquer valor não previsto nos casos anteriores, como um else.

1. Seleção por valor exato com match e case #

Quando temos um código numérico ou uma sigla e queremos executar uma ação específica para cada valor exato, escrevemos match variavel: e listamos abaixo as cláusulas case valor_literal:.

O Python compara o valor da expressão do match com cada case de cima para baixo. Ao encontrar o primeiro case que coincide, executa seu bloco indentado e encerra o match automaticamente (em Python não existe queda acidental para o próximo case, portanto não é preciso escrever break ao final de cada caso).

Python
canal_entrega = 2

match canal_entrega:
    case 1:
        modalidade = "Entrega padrão em domicílio"
        prazo_horas = 48
    case 2:
        modalidade = "Retirada rápida na loja"
        prazo_horas = 2
    case 3:
        modalidade = "Entrega expressa no mesmo dia"
        prazo_horas = 6

print(modalidade, "- Prazo:", prazo_horas, "h")

Saída: Retirada rápida na loja - Prazo: 2 h

2. O padrão curinga: case _ #

O que acontece se o operador digitar o código 99 em um menu que só prevê as opções 1, 2 e 3? Se nenhum case coincidir e não houver um caso padrão, o programa simplesmente passará pelo match sem executar nenhum bloco — e variáveis que deveriam ser criadas lá dentro poderão ficar indefinidas!

Para tratar qualquer valor não previsto, colocamos por último o caso curinga case _:. O sublinhado (_) captura qualquer valor restante, desempenhando exatamente o papel do else final.

Python
codigo_setor = 99

match codigo_setor:
    case 10:
        nome_setor = "Perfumaria"
        taxa = 5
    case 20:
        nome_setor = "Dermocosméticos"
        taxa = 8
    case 30:
        nome_setor = "Higiene Pessoal"
        taxa = 3
    case _:
        nome_setor = "Setor não cadastrado"
        taxa = 0

print(nome_setor, "| Taxa interna:", taxa)

Saída: Setor não cadastrado | Taxa interna: 0

REGRA DE POSIÇÃO

O padrão curinga case _: deve ser sempre o ÚLTIMO caso do match. Como ele aceita qualquer valor, nada abaixo dele seria alcançado.

3. Seleção com textos (str) e maiúsculas vs. minúsculas #

Além de números inteiros, match/case funciona muito bem com textos literais, como siglas de turno ("M", "T", "N") ou formas de pagamento ("PIX", "CARTAO", "DINHEIRO").

Lembre-se de que o Python diferencia letras maiúsculas de minúsculas: o texto "m" não coincide com case "M":.

Python
turno = "T"

match turno:
    case "M":
        horario = "08h às 14h (Manhã)"
    case "T":
        horario = "14h às 20h (Tarde)"
    case "N":
        horario = "20h às 22h (Noite)"
    case _:
        horario = "Sigla de turno inválida"

print("Escala:", horario)

Saída: Escala: 14h às 20h (Tarde)

4. Agrupando literais equivalentes com | #

Quando vários valores literais devem executar exatamente a mesma ação — por exemplo, aceitar tanto "S" quanto "s", ou agrupar os dias úteis 2, 3, 4, 5 e 6 —, podemos uni-los no mesmo case usando a barra vertical (|), que significa 'ou' entre padrões.

Isso evita duplicar linhas de código idênticas para variações do mesmo comando.

Python
confirmacao = "s"

match confirmacao:
    case "S" | "s" | "SIM" | "sim":
        print("Operação confirmada pelo caixa.")
    case "N" | "n" | "NAO" | "nao":
        print("Operação cancelada.")
    case _:
        print("Resposta não reconhecida.")

Saída: Operação confirmada pelo caixa.

Padrão escrito no caseValores que entram nesse blocoVantagem
case "S" | "s":"S" maiúsculo ou "s" minúsculoAceita ambas as grafias sem repetir o bloco.
case 1 | 7:Inteiro 1 (domingo) ou 7 (sábado)Agrupa códigos de fim de semana em uma única regra.
case 2 | 3 | 4 | 5 | 6:Inteiros de 2 a 6Agrupa dias úteis com clareza.

5. Quando usar match/case e quando preferir if/elif/else #

Embora muitas seleções possam ser escritas das duas maneiras, cada estrutura tem seu ponto forte claro:

• Escolha match/case quando a decisão comparar uma única expressão contra valores literais discretos e bem conhecidos (opções de menu 1, 2, 3; códigos de status; siglas).

• Escolha if/elif/else quando a decisão envolver intervalos numéricos (<, <=, >, >=), cálculos relacionais entre variáveis diferentes (pedido <= estoque) ou condições booleanas combinadas.

Python
# Comparação lado a lado para códigos literais:
opcao = 1

match opcao:
    case 1:
        print("Consulta de preço")
    case 2:
        print("Baixa de estoque")
    case _:
        print("Opção inválida")

Saída: Consulta de preço

Natureza da regra de negócioEstrutura recomendadaExemplo

6. Estudo acompanhado: cálculo de frete por região #

Podemos usar o bloco de cada case para definir alíquotas ou taxas e, depois do match, realizar o cálculo final somente se o código informado for válido.

Python
regiao = 2
valor_pedido = 120.0

match regiao:
    case 1:
        nome_regiao = "Capital"
        frete = 10.0
    case 2:
        nome_regiao = "Interior"
        frete = 22.0
    case _:
        nome_regiao = "Inválida"
        frete = -1.0

if frete >= 0:
    total = valor_pedido + frete
    print(f"Região: {nome_regiao} | Total com frete: R$ {total:.2f}")
else:
    print("Erro: código de região inexistente.")

Saída: Região: Interior | Total com frete: R$ 142.00
