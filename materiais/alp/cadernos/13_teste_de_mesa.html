Entenda a ideia

Executar mentalmente com um registro explícito

Teste de mesa é acompanhar instrução por instrução sem depender do computador. Prepare colunas para o ponto de execução, variáveis relevantes, condições e saída. Registre o estado inicial. Em cada atribuição, avalie o lado direito com os valores daquele instante e só então atualize o lado esquerdo. Uma previsão sem registro intermediário pode esconder um raciocínio incorreto.

Fronteiras revelam regras esquecidas

Escolha casos que façam o programa tomar caminhos distintos: abaixo, igual e acima de um limite; laço com nenhuma, uma e várias repetições; sentinela como primeira leitura; empate entre valores. O caso comum mostra que um caminho funciona, mas não verifica todos os limites. Escreva o resultado esperado antes de executar para não ajustar a previsão ao que o programa produziu.

Comparar a primeira divergência

Execute o programa depois de concluir a tabela e compare os estados. Ao encontrar uma diferença, procure a primeira instrução em que previsão e execução se separam. Uma divergência posterior pode ser apenas consequência dela. Corrija o raciocínio ou o código, repita os casos e explique a propriedade que deve permanecer verdadeira. O objetivo é justificar o comportamento, não apenas obter uma saída que pareça correta.

Erros para observar

Registrar só o resultado final; omitir a condição que encerra o laço; misturar estado local e externo; escolher os resultados esperados somente depois de observar o programa.

Leia o código antes de avançar. Cada passo explica uma mudança ou decisão. A simulação tem uma sequência fixa; os arquivos Python permitem experimentar outras entradas.

# 05 — Rastrear chamadas e retornos
# Objetivo: Manter separados os estados do chamador e da função.
# Pré-requisitos: exemplos anteriores deste tópico e tópicos anteriores.
# Observe: Cada chamada começa com novos valores locais.
# Como estudar: preveja a saída, execute e altere um valor por vez.

# Confira na saída: 'Resultado: 5'

def incrementar(valor):
    """Retorne o inteiro valor acrescido de um."""
    valor += 1
    return valor

# etapa                    | externo | local valor | retorno
# externo = 3              | 3       | —           | —
# incrementar(externo)     | 3       | 3 -> 4      | 4
# resultado recebe retorno | 3       | —           | 4
# incrementar(resultado)   | 3       | 4 -> 5      | 5
externo = 3
resultado = incrementar(externo)
resultado = incrementar(resultado)
print("Externo:", externo)
print("Resultado:", resultado)
06 — Verificação e invarianteBaixar este exemplo .py
# 06 — Verificação e invariante
# Objetivo: Explicar por que um resultado é coerente.
# Pré-requisitos: exemplos anteriores deste tópico e tópicos anteriores.
# Observe: Invariante é uma propriedade que permanece válida durante a repetição.
# Como estudar: preveja a saída, execute e altere um valor por vez.
# Execução guiada: este exemplo não solicita entrada.
# Confira na saída: 'Verificações concluídas'

def somar_ate(limite):
    """Retorne 1 + ... + limite; limite deve ser inteiro não negativo."""
    soma = 0
    # Antes de cada volta, soma contém os inteiros anteriores a atual.
    for atual in range(1, limite + 1):
        soma += atual
        # Depois da volta, soma contém os inteiros de 1 até atual.
    return soma

# Para limite 3: (atual, soma após corpo) é 1/1, 2/3, 3/6.
# Não construímos pares ou coleções; esta é só uma anotação no papel.
assert somar_ate(0) == 0  # Caso sem repetições.
assert somar_ate(1) == 1  # Menor caso com uma repetição.
assert somar_ate(3) == 6  # Caso usual.
# assert serve para conferir hipóteses, não para validar entrada de usuário.
for limite in range(6):
    esperado = limite * (limite + 1) // 2
    assert somar_ate(limite) == esperado
print("Verificações concluídas")
# Se o laço usasse range(1, limite), o caso limite 1 revelaria a falha.

# Rastrear um saldo — cenário didático Lojas Blue
# Objetivo: Conferir o limite de retirada por teste de mesa.
# Pré-requisito: tópicos anteriores e exemplos anteriores deste tópico.
# Estude: preveja o resultado, execute e altere um dado por vez.
# Confira na saída: 'Saldo final: 0'
# Sem entrada interativa.

# Simulação: retiradas fixas de três unidades até não haver saldo.
# avaliação | saldo antes | saldo >= 3 | retiradas após corpo
# 1         | 6           | True       | 1
# 2         | 3           | True       | 2
# 3         | 0           | False      | não executa
saldo = 6
retiradas = 0
while saldo >= 3:
    saldo -= 3
    retiradas += 1
print("Retiradas:", retiradas)
print("Saldo final:", saldo)
# Refazer a tabela com saldo sete mostra por que pode haver restante.
