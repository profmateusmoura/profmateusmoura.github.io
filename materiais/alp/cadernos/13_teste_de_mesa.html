Percurso deste caderno #

Um programa pode executar do início ao fim sem apresentar nenhuma mensagem de erro do Python e, ainda assim, cobrar o preço errado ou deixar um cliente elegível sem desconto. A ferramenta mais poderosa para compreender qualquer algoritmo e diagnosticar erros lógicos antes ou depois de rodar o código é o teste de mesa: simular a execução linha por linha como se você fosse o próprio interpretador Python.

Pré-requisito: Cadernos 01 a 12 (Todos os fundamentos de Algoritmos e Lógica de Programação).

1. O que é o teste de mesa e como montar a tabela #

Fazer um teste de mesa consiste em executar o código manualmente, instrução por instrução, registrando em uma tabela o valor exato de cada variável após cada linha executada.

A regra fundamental do teste de mesa é nunca adivinhar o resultado de cabeça pulando etapas: quando uma linha faz y = y - x, você deve consultar na linha imediatamente anterior da tabela quanto valem y e x naquele exato momento.

Python
x = 4
y = 10
x = x + 3
y = y - x
x = x * 2
print(x, y)

Saída: 14 3

Linha executadaValor de xValor de ySaída na tela
1. x = 44——
2. y = 10410—
3. x = x + 37 (4 + 3)10—
4. y = y - x73 (10 - 7, usando o novo x!)—
5. x = x * 214 (7 * 2)3—
6. print(x, y)14314 3

2. Teste de mesa em decisões e valores de fronteira #

Para verificar se um if/elif/else está correto, um único caso de teste não basta. Precisamos escolher casos estrategicamente nas fronteiras onde o comportamento muda.

Por exemplo, se a regra da Lojas Blue diz 'frete grátis para compras a partir de R$ 100', a fronteira exata é 100. Devemos testar pelo menos três valores: 99 (logo abaixo da fronteira), 100 (exatamente na fronteira) e 101 (logo acima da fronteira). O valor 100 é o que desmascara imediatamente quem escreveu > 100 em vez de >= 100!

Python
# Verificando a fronteira exata compra = 100:
compra = 100

if compra >= 100:
    frete = 0
else:
    frete = 15

print("Compra:", compra, "| Frete:", frete)

Saída: Compra: 100 | Frete: 0

Caso de testeResultado esperado pela regraCódigo correto (compra >= 100)Código com bug (compra > 100)
compra = 99 (abaixo)Frete 1599 >= 100 False → 1599 > 100 False → 15 (esconde o bug)
compra = 100 (fronteira exata)Frete 0100 >= 100 True → 0100 > 100 False → 15 (REVELA O BUG!)
compra = 101 (acima)Frete 0101 >= 100 True → 0101 > 100 True → 0 (esconde o bug)

3. Rastreando laços while e for volta a volta #

Ao fazer o teste de mesa de um laço, crie uma linha na tabela para cada verificação da condição. Acompanhe na ordem exata em que as linhas estão posicionadas dentro do bloco: faz muita diferença somar antes de incrementar o contador ou incrementar o contador antes de somar!

Python
k = 1
acum = 0

while k <= 3:
    acum = acum + k * 2
    k = k + 1

print("Final -> k:", k, "| acum:", acum)

Saída: Final -> k: 4 | acum: 12

PassagemTeste k <= 3acum = acum + k * 2k = k + 1
Início—acum = 0k = 1
1ª volta1 <= 3 → True0 + 1*2 = 2k passa a 2
2ª volta2 <= 3 → True2 + 2*2 = 6k passa a 3
3ª volta3 <= 3 → True6 + 3*2 = 12k passa a 4
Saída do laço4 <= 3 → False(permanece 12)(termina valendo 4)

4. Rastreando chamadas de funções e retornos #

Quando uma linha contém uma chamada de função, anotamos os argumentos enviados, abrimos um quadro local para os parâmetros da função, acompanhamos o cálculo até o return e substituímos a chamada pelo valor devolvido.

Python
def taxa_entrega(distancia_km):
    if distancia_km <= 5:
        return 8
    return 8 + (distancia_km - 5) * 2

pedido1 = taxa_entrega(4)
pedido2 = taxa_entrega(8)
print("Taxas:", pedido1, "e", pedido2)

Saída: Taxas: 8 e 14

ChamadaValor do parâmetro distancia_kmTeste distancia_km <= 5Valor devolvido por return
taxa_entrega(4)44 <= 5 → True8
taxa_entrega(8)88 <= 5 → False8 + (8 - 5) * 2 = 14

5. Catálogo de bugs clássicos revelados pelo teste de mesa #

Quase todos os erros lógicos em Algoritmos e Lógica de Programação pertencem a cinco famílias recorrentes que o teste de mesa identifica na primeira simulação:

Python
# Bug corrigido: acumulador fora do laço e limite inclusivo range(1, 4)
soma = 0
for item in range(1, 4):
    soma = soma + item * 10
print("Soma correta dos 3 itens:", soma)

Saída: Soma correta dos 3 itens: 60

Família do bugSintoma observadoCausa no códigoCorreção
Erro por um (off-by-one)Laço executa 1 vez a menos ou a mais.Usou range(1, n) em vez de range(1, n + 1), ou < em vez de <=.Ajustar o limite final ou o operador relacional.
Acumulador zerado no laçoA soma final mostra apenas o último valor lido.soma = 0 foi colocado dentro do while/for.Mover soma = 0 para antes do cabeçalho do laço.
Ordem invertida no whileO valor sentinela (0) entra na contagem/soma.Lê o próximo valor antes de somar o anterior.Ler o 1º antes do while e os demais na última linha do bloco.
Faixa sombreada no elifFaixas maiores nunca são alcançadas.Testou >= 50 antes de >= 200.Ordenar os testes do mais restritivo (maior) para o menor.
Função devolve NoneTypeError ao tentar somar o resultado da função.Usou print() dentro da função e esqueceu o return.Trocar ou complementar por return resultado.

6. Roteiro de verificação antes de concluir um exercício #

Sempre que terminar de escrever um programa na IDE, passe por este checklist de 4 testes rápidos:

1. Caso típico: os valores normais do enunciado batem com a saída esperada?

2. Caso de fronteira: o que acontece exatamente nos limites (0, 1, 10, 100)?

3. Caso mínimo ou parada imediata: o que acontece se a primeira leitura já for o sentinela 0?

4. Explicação em voz alta: você consegue explicar o papel de cada variável da sua tabela de estados?

Python
a = 2
b = 5
aux = a
a = b + 1
b = aux * 2
print("Verificação final concluída -> a:", a, "| b:", b)

Saída: Verificação final concluída -> a: 6 | b: 4
