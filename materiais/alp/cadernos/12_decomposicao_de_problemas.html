Como estudar este caderno

Leia as seções na ordem. Cada uma desenvolve uma ideia, mostra como ela aparece no código e explica o resultado. Os códigos curtos do texto são exemplos de leitura; o pacote ZIP reúne os programas completos e os exercícios para praticar depois.

Antes de executar um código, preveja o que será exibido. Compare a previsão com a explicação e observe qual instrução produz cada mudança. Não é necessário acertar de primeira: localizar a diferença faz parte do estudo.

No mundo físico

Divida um atendimento em responsabilidades: receber informação, conferir, calcular e comunicar. A passagem de informação entre etapas precisa estar definida.

1. Transformar uma tarefa grande em responsabilidades

Um orçamento pode envolver leitura, validação, cálculo e apresentação. Escrever tudo em um bloco dificulta verificar cada parte. Decomponha o problema descrevendo tarefas pequenas e seus contratos. A função de cálculo não precisa perguntar dados ao usuário; ela recebe valores já aceitos. A função de apresentação não precisa repetir a fórmula.

2. Separe leitura, cálculo e apresentação

Uma função de cálculo que chama input e print ao mesmo tempo assume responsabilidades difíceis de reutilizar. Para testar uma fórmula, você teria de repetir uma interação completa. Se ela apenas recebe números e devolve um resultado, pode ser conferida com valores fixos e utilizada em outras situações.

A separação não exige criar uma função para cada linha. Agrupe uma tarefa que tenha significado e um contrato claro. Ler uma quantidade válida, calcular uma falta e apresentar um resumo são responsabilidades reconhecíveis. Use main para coordená-las, mantendo visível a ordem em que os dados atravessam o programa.

3. Planejar o caminho dos dados

Desenhe quem chama quem e qual valor cada função devolve. Uma função principal pode coordenar as etapas: obter valores, chamar cálculos e mostrar o resultado. Se uma função precisa de um dado, prefira passá-lo por parâmetro em vez de depender silenciosamente de uma variável externa. Essa relação explícita permite testar uma parte com valores fixos.

4. Uma função pode usar o resultado de outra

Ao compor funções, o resultado da primeira precisa atender ao contrato da próxima operação. Se uma devolve um percentual e outra espera uma proporção, os números podem parecer aceitáveis, mas o cálculo estará errado. A unidade de cada argumento deve ser tão clara quanto seu tipo.

No exemplo, a função de desconto devolve um valor monetário, não o preço final. A função principal da conta subtrai esse valor do preço. Nomear o retorno de acordo com seu significado ajuda a evitar usar um total no lugar de uma parcela.

Python · exemplo explicado
def valor_desconto(preco, percentual):
    """Devolve a parcela de desconto, com percentual entre 0 e 100."""
    return preco * percentual / 100

def preco_final(preco, percentual):
    """Devolve o preço após retirar o desconto calculado."""
    return preco - valor_desconto(preco, percentual)

print(preco_final(80, 10))
Resultado
72.0

Como ler a execução

valor_desconto devolve 8. preco_final usa esse retorno para calcular 80 - 8. A apresentação é feita pelo chamador externo.

5. Integrar depois de conferir as partes

Primeiro teste funções pequenas em casos comuns e de fronteira. Depois execute a sequência completa, verificando se a saída de uma etapa atende à entrada da próxima. Não basta cada função funcionar isoladamente se elas discordam sobre unidades ou domínio. Nos projetos do caderno, os leitores e os contratos devem ser respeitados; erros de entrada são tratados na etapa de leitura, antes do cálculo.

6. Teste as partes antes da integração

Escolha valores simples para testar cada contrato. Uma função de falta de estoque deve devolver zero quando não existe falta; uma função de subtotal deve respeitar preço e quantidade no domínio declarado. Só depois conecte os leitores, os cálculos e a apresentação.

No teste integrado, acompanhe a passagem do valor: o leitor realmente devolveu um número? A função recebeu os argumentos na ordem certa? O resultado foi usado ou apenas impresso e descartado? Uma falha de integração pode ocorrer mesmo quando as funções isoladas estão corretas. Registre também o que a função não faz: uma função de cálculo não deve atualizar silenciosamente um saldo externo.

Um exemplo acompanhado

Leia o código antes de avançar. Cada passo explica uma mudança ou decisão. A simulação tem uma sequência fixa; os arquivos Python permitem experimentar outras entradas.

def subtotal(preco, quantidade):
    """Calcula o subtotal para preço e quantidade não negativos."""
    return preco * quantidade

def main():
    """Coordena um orçamento com valores de demonstração."""
    valor = subtotal(10, 3)
    print(valor)

main()
Conferir a saída
30
