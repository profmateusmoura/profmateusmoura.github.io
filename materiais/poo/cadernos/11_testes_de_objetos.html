Testar comportamentos de objetos

Conferir sequências de chamadas, limites e preservação de estado.

COMO ESTUDAR

Leia as explicações em ordem, acompanhe o código e só depois abra os exemplos completos no ZIP. Não é preciso ter usado classes antes de começar esta trilha.

1. Testar o contrato observável #

Um teste prepara uma situação, executa uma operação e confere o resultado observável. Para um estoque, isso inclui o saldo posterior. Atributos internos são detalhes da implementação; prefira a interface pública quando ela oferece o que precisa ser observado.

Nomeie os testes pelo comportamento que descrevem: retirar todo o saldo, recusar quantidade negativa, preservar o estado após falha. Um teste com nome claro também ajuda a documentar a regra para quem mantém o programa.

2. Uma falha também tem resultado esperado #

Não basta testar apenas o caminho feliz. Uma retirada acima do saldo deve gerar a falha prevista e manter o saldo. Teste essas duas partes. Também considere o limite exato: retirar todo o saldo é diferente de retirar mais que o saldo.

Cada teste deve construir seu próprio estado, para que a ordem de execução não decida o resultado. Um objeto compartilhado por testes pode carregar alterações de um caso para outro e esconder dependências indesejadas.

3. unittest faz parte da biblioteca padrão #

unittest oferece casos de teste e asserções para comparar resultados e esperar exceções. No pacote, os exemplos deste caderno contêm verificações simples executáveis para mostrar as mesmas regras de modo curto; os exercícios pedem sua organização em TestCase.

Uma suíte de testes não prova ausência de todos os erros. Ela registra os casos escolhidos e protege comportamentos relevantes durante mudanças. Ao corrigir um defeito, inclua um caso que falhe antes da correção e passe depois, sem apenas repetir a implementação linha por linha.

4. Um exemplo acompanhado

O programa abaixo é completo e independente. Antes de executar, procure o estado inicial e a operação que produz o resultado. Os comentários documentam as responsabilidades.

Python
class Estoque:
    """Mantém saldo inteiro não negativo para testes de comportamento."""

    def __init__(self, saldo):
        """Valida o saldo inicial."""
        if type(saldo) is not int or saldo < 0:
            raise ValueError("Saldo inválido")
        self.saldo = saldo

    def retirar(self, quantidade):
        """Valida antes de alterar; quantidade deve ser inteira positiva."""
        if type(quantidade) is not int or quantidade <= 0 or quantidade > self.saldo:
            raise ValueError("Retirada inválida")
        self.saldo -= quantidade

e = Estoque(5)
e.retirar(2)
assert e.saldo == 3
print("Caso comum: OK")
Saída
Caso comum: OK

Compare outras duas situações

Os trechos seguintes usam as mesmas definições acima. Cada um começa com novos objetos; não reutilize o estado de uma execução anterior.

Fronteira

Python
e = Estoque(5)
e.retirar(5)
assert e.saldo == 0
print("Fronteira: OK")
Saída
Fronteira: OK

Falha e estado

Python
e = Estoque(5)
try:
    e.retirar(6)
except ValueError:
    pass
else:
    raise AssertionError("A retirada deveria falhar")
assert e.saldo == 5
print("Falha preserva estado: OK")
Saída
Falha preserva estado: OK
