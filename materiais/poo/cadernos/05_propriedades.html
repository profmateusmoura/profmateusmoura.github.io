Propriedades e interfaces

Expor atributos de forma controlada, sem prometer privacidade absoluta.

COMO ESTUDAR

Leia as explicações em ordem, acompanhe o código e só depois abra os exemplos completos no ZIP. Não é preciso ter usado classes antes de começar esta trilha.

1. Uma leitura simples com uma regra por trás #

Uma propriedade permite oferecer uma sintaxe de atributo enquanto a classe controla sua leitura ou escrita. Em produto.preco_centavos, o chamador vê uma informação; a implementação pode executar um método getter. Isso permite manter uma interface simples sem espalhar conhecimento sobre o atributo interno.

Use propriedades quando elas fazem sentido para o contrato. Não é necessário criar getters e setters para todo campo por hábito. Uma propriedade somente de leitura pode ser a escolha certa quando alterações devem ocorrer por operações específicas.

2. Validar também as alterações posteriores #

Se um preço pode mudar, o setter deve validar a nova entrada. É comum fazer __init__ usar esse mesmo caminho de validação, para não duplicar a regra. O exemplo guarda centavos inteiros: 2490 representa R$ 24,90. Isso evita depender de aproximações de float para o valor armazenado.

O sublinhado em _preco_centavos continua sendo uma convenção de uso interno. A propriedade orienta a interface pública; não impede uma pessoa de alterar deliberadamente atributos internos.

3. Unidades fazem parte do contrato #

Um número sozinho não explica se representa reais ou centavos. Deixe a unidade no nome e na documentação. Ao ler dados externos, a conversão deve ocorrer em um ponto explícito, não silenciosamente em várias classes.

Os dados deste caderno são pequenos e sintéticos. Não estamos convertendo automaticamente os preços da base de PED. Quando houver integração com arquivos, o adaptador deverá declarar e validar o formato recebido.

4. Um exemplo acompanhado

O programa abaixo é completo e independente. Antes de executar, procure o estado inicial e a operação que produz o resultado. Os comentários documentam as responsabilidades.

Python
class Produto:
    """Guarda preço em centavos inteiros não negativos."""

    def __init__(self, preco_centavos):
        """Usa a propriedade para validar o estado inicial."""
        self.preco_centavos = preco_centavos

    @property
    def preco_centavos(self):
        """Devolve o preço armazenado."""
        return self._preco_centavos

    @preco_centavos.setter
    def preco_centavos(self, valor):
        """Valida antes de substituir o preço."""
        if type(valor) is not int or valor < 0:
            raise ValueError("Preço inválido")
        self._preco_centavos = valor

p = Produto(2490)
print(p.preco_centavos)
Saída
2490

Compare outras duas situações

Os trechos seguintes usam as mesmas definições acima. Cada um começa com novos objetos; não reutilize o estado de uma execução anterior.

Alterar preco

Python
p = Produto(2490)
p.preco_centavos = 1990
print(p.preco_centavos)
Saída
1990

Recusar preco

Python
p = Produto(2490)
try:
    p.preco_centavos = -1
except ValueError as erro:
    print(erro)
print(p.preco_centavos)
Saída
Preço inválido
2490

6. O que levar deste caderno

Expor atributos de forma controlada, sem prometer privacidade absoluta. Não. Ela define uma interface controlada; o sublinhado é uma convenção, não uma barreira de segurança.

Ao explicar uma solução, identifique quem guarda os dados, quem pode alterá-los e quais condições precisam continuar verdadeiras. Se não conseguir justificar uma mudança, volte ao código e acompanhe a primeira instrução em que sua previsão divergiu.
