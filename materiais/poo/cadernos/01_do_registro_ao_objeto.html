Do registro ao objeto

Reconhecer estado, comportamento e responsabilidade antes de escrever classes.

COMO ESTUDAR

Leia as explicações em ordem, acompanhe o código e só depois abra os exemplos completos no ZIP. Não é preciso ter usado classes antes de começar esta trilha.

1. Uma situação que você já conhece #

Em PED, um produto pode ser representado por um dicionário com nome e estoque. Funções recebem esse registro e realizam operações. Essa organização continua válida. POO oferece outra forma de reunir informações e operações relacionadas, e não uma obrigação de substituir qualquer dicionário por uma classe.

Imagine várias partes de um sistema alterando o estoque diretamente. Cada uma precisa lembrar as mesmas regras: uma retirada deve ser positiva e não pode ultrapassar o saldo. Quando essas regras ficam espalhadas, uma alteração pode esquecer uma verificação. A primeira pergunta de projeto é onde a responsabilidade pela regra deve ficar.

2. Separar estado de comportamento #

Estado é a informação que descreve a situação atual: por exemplo, o nome e a quantidade disponível. Comportamento é uma operação que usa ou transforma esse estado: retirar unidades, consultar disponibilidade ou calcular uma falta. No início, podemos identificar essas partes mesmo usando apenas funções e dicionários.

Um objeto não é uma representação completa de uma empresa real. Ele é um modelo escolhido para resolver um problema. Para uma retirada didática, não precisamos inventar endereço, fornecedor ou histórico de vendas. Incluir só o necessário torna a regra mais fácil de entender e testar.

3. Um contrato antes da sintaxe #

Antes de definir uma classe, escreva o contrato da operação: quais entradas aceita, qual resultado produz e o que deve acontecer se não puder realizá-la. Uma operação recusada deve preservar o estoque. Valide antes de modificar.

Os exemplos deste caderno são procedurais de propósito: mostram o ponto de partida conhecido de ALP e PED. Nos próximos cadernos, vamos reorganizar a mesma ideia com classes e métodos. A mudança importante será a atribuição de responsabilidade, não apenas o lugar dos parênteses.

4. Um exemplo acompanhado

O programa abaixo é completo e independente. Antes de executar, procure o estado inicial e a operação que produz o resultado. Os comentários documentam as responsabilidades.

Python
def retirar(produto, quantidade):
    """Retira um inteiro positivo se houver saldo; falhas preservam o registro."""
    if type(quantidade) is not int or quantidade <= 0:
        raise ValueError("Quantidade deve ser um inteiro positivo")
    if quantidade > produto["estoque"]:
        raise ValueError("Saldo insuficiente")
    produto["estoque"] -= quantidade

produto = {"nome": "Shampoo", "estoque": 8}
retirar(produto, 3)
print(produto["estoque"])

Python
produto = {"nome": "Batom", "estoque": 2}
try:
    retirar(produto, 3)
