Herança e especialização

Usar herança quando existe uma relação coerente de substituição.

COMO ESTUDAR

Leia as explicações em ordem, acompanhe o código e só depois abra os exemplos completos no ZIP. Não é preciso ter usado classes antes de começar esta trilha.

1. Uma especialização preserva um contrato #

Herança permite definir uma classe a partir de outra e especializar comportamentos. Uma EntregaExpressa pode ser tratada como uma entrega se respeitar o contrato esperado para esse papel. Reutilizar algumas linhas não basta para justificar a relação: é preciso que o subtipo faça sentido nos lugares em que o tipo base é usado.

O exemplo calcula um prazo didático. A classe base representa uma entrega com prazo padrão; a expressa mantém a mesma operação, mas fornece outro resultado. Não estamos implementando cálculo real de logística.

2. Sobrescrever não é mudar arbitrariamente a interface #

Ao sobrescrever prazo_dias, mantemos uma chamada sem argumentos explícitos e um resultado inteiro positivo. Se a classe derivada passasse a exigir um argumento extra ou devolvesse um texto incompatível, o código cliente poderia deixar de funcionar.

Essa observação aproxima a ideia de substituição: um cliente que usa o contrato de entrega deve continuar entendendo o resultado. Herança cria uma promessa sobre comportamento, não apenas uma conexão sintática entre nomes de classes.

3. super e composição têm papéis distintos #

super permite aproveitar uma implementação da hierarquia, inclusive sua inicialização, quando isso é adequado. Ele não é uma obrigação em todo método sobrescrito. Quando um objeto apenas utiliza um serviço de outro tipo, composição costuma representar melhor a relação.

Comece com hierarquias pequenas. Classes muito profundas exigem procurar regras em muitos lugares. No estudo inicial, prefira uma base e uma especialização com um motivo claro, testes simples e contratos documentados.

4. Um exemplo acompanhado

O programa abaixo é completo e independente. Antes de executar, procure o estado inicial e a operação que produz o resultado. Os comentários documentam as responsabilidades.

Python
class Entrega:
    """Fornece um prazo didático em dias inteiros positivos."""

    def prazo_dias(self):
        """Retorna o prazo padrão."""
        return 5


class EntregaExpressa(Entrega):
    """Especializa a entrega mantendo o contrato de consulta."""

    def prazo_dias(self):
        """Retorna um prazo menor neste cenário didático."""
        return 2

print(Entrega().prazo_dias())
Saída
5

Compare outras duas situações

Os trechos seguintes usam as mesmas definições acima. Cada um começa com novos objetos; não reutilize o estado de uma execução anterior.

Prazo especializado

Python
print(EntregaExpressa().prazo_dias())
Saída
2

Mesma interface

Python
for entrega in [Entrega(), EntregaExpressa()]:
    print(entrega.prazo_dias())

6. O que levar deste caderno

Usar herança quando existe uma relação coerente de substituição. Não. A relação também precisa preservar o significado e o contrato esperado pelos clientes.

Ao explicar uma solução, identifique quem guarda os dados, quem pode alterá-los e quais condições precisam continuar verdadeiras. Se não conseguir justificar uma mudança, volte ao código e acompanhe a primeira instrução em que sua previsão divergiu.
