Composição de objetos

Construir uma colaboração entre objetos sem recorrer imediatamente à herança.

COMO ESTUDAR

Leia as explicações em ordem, acompanhe o código e só depois abra os exemplos completos no ZIP. Não é preciso ter usado classes antes de começar esta trilha.

1. Um objeto pode usar outro #

Uma linha de pedido contém informações sobre um produto e uma quantidade. Ela pode referenciar um objeto Produto em vez de repetir seus campos. Chamamos essa relação de composição no desenho do modelo: uma parte colabora com outra para realizar uma tarefa.

Antes de pensar em herança, pergunte se a relação significa “é um tipo de” ou “tem/usa um”. Uma linha de pedido não é um produto; ela usa um produto. Forçar essa relação como herança faria o modelo expressar algo diferente do problema.

2. Decidir quando um valor deve ser copiado #

Se a linha consulta o preço atual do produto toda vez que calcula o total, uma alteração no catálogo pode mudar um pedido já registrado. Talvez isso seja desejado em uma simulação de orçamento, mas não em uma venda confirmada. A decisão precisa ser explícita.

Neste exemplo, a linha guarda uma fotografia do preço no momento de sua criação. O nome continua vindo da referência ao produto, mas o preço utilizado no subtotal é o valor capturado. Essas escolhas mostram que modelar relações exige pensar no tempo, e não apenas nos tipos.

3. Responsabilidades pequenas se conectam #

Produto representa dados de catálogo; LinhaPedido conhece quantidade e preço aplicado. A linha calcula seu subtotal sem precisar perguntar detalhes ao usuário nem gravar arquivos. Essa separação facilita a conferência.

O exemplo pressupõe um objeto Produto válido. As validações se concentram na quantidade e no preço do produto. Conforme o sistema crescer, mantenha explícito o contrato de cada colaboração e evite uma classe que realize todas as tarefas da aplicação.

4. Um exemplo acompanhado

O programa abaixo é completo e independente. Antes de executar, procure o estado inicial e a operação que produz o resultado. Os comentários documentam as responsabilidades.

Python
class Produto:
    """Representa um preço de catálogo didático."""

    def __init__(self, nome, preco_centavos):
        """Recebe nome e preço inteiro não negativo."""
        if type(preco_centavos) is not int or preco_centavos < 0:
            raise ValueError("Preço inválido")
        self.nome = nome
        self.preco_centavos = preco_centavos


class LinhaPedido:
    """Usa um produto e preserva o preço aplicado na criação."""

    def __init__(self, produto, quantidade):
        """Recebe produto válido e quantidade inteira positiva."""
        if type(quantidade) is not int or quantidade <= 0:
            raise ValueError("Quantidade inválida")
        self.produto = produto
        self.quantidade = quantidade
        self.preco_aplicado = produto.preco_centavos

    def subtotal(self):
        """Calcula usando a fotografia do preço."""
        return self.quantidade * self.preco_aplicado

p = Produto("Shampoo", 1000)
linha = LinhaPedido(p, 3)
print(linha.subtotal())
Saída
3000
