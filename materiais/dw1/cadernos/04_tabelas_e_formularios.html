1. Dados Tabulares e Entrada de Dados na Vitrine #

Em um e-commerce real como a Lojas Blue, precisamos exibir comparativos técnicos de produtos e resumos de pedidos (onde linhas e colunas se cruzam) e também coletar informações da pessoa cliente: busca de produtos, cálculo de CEP, escolha de frete e cadastro de checkout.

Para dados bidimensionais usamos tabelas semânticas (<table>) — jamais para desenhar layout de página! Já para coletar e validar dados do usuário usamos formulários HTML5 (<form>) com controles acessíveis e validação nativa integrada ao navegador.

TODO CAMPO DE FORMULÁRIO PRECISA DE UM <LABEL> EXPLÍCITO

O atributo placeholder é apenas uma dica temporária que desaparece assim que o usuário começa a digitar. Nunca substitua o <label for="id"> por placeholder: o label garante acessibilidade e ainda amplia a área de clique (especialmente útil em checkboxes e radios no celular).

2. Tabelas com scope e Formulários com Validação Nativa #

Veja lado a lado a anatomia de uma tabela de pedido e um formulário de fechamento de compra:

HTML
<!-- 1. Tabela de Dados Acessível -->
<table>
  <caption>Resumo do Pedido #904 — Lojas Blue</caption>
  <thead>
    <tr>
      <th scope="col">Produto</th>
      <th scope="col">Qtd</th>
      <th scope="col">Subtotal</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <th scope="row">Mouse Sem Fio Ergo</th>
      <td>2</td>
      <td>R$ 280,00</td>
    </tr>
  </tbody>
  <tfoot>
    <tr>
      <th scope="row" colspan="2">Total do Pedido</th>
      <td>R$ 280,00</td>
    </tr>
  </tfoot>
</table>

<!-- 2. Formulário com Validação Nativa -->
<form action="/checkout" method="post">
  <fieldset>
    <legend>Dados para Entrega</legend>

    <label for="email-cliente">E-mail para nota fiscal</label>
    <input id="email-cliente" name="email" type="email" required placeholder="voce@exemplo.com">

    <label for="cep-destino">CEP (8 dígitos)</label>
    <input id="cep-destino" name="cep" type="text" required pattern="[0-9]{5}-?[0-9]{3}">

    <button type="submit">Confirmar Pedido</button>
  </fieldset>
</form>
Atributo / ElementoOnde é usadoComportamento Técnico
scope="col" / scope="row"Na tag <th>Indica se o cabeçalho rotula toda a coluna abaixo ou toda a linha à direita
for="id" + id="id"Par <label> e <input>Conecta semanticamente o rótulo ao campo e transfere o foco ao clicar no texto
name="chave"Em inputs, selects e textareasDefine o nome da chave enviada ao servidor (sem name, o dado não é enviado!)
required, min, max, patternNos controles de entradaImpede o envio de dados inválidos usando a validação nativa do navegador

3. Simulador Visual Ao Vivo: Validação e Payload do Formulário #

Teste o preenchimento dos campos abaixo para ver como os atributos name e value são empacotados e como a validação nativa reage:

ID VS. NAME EM BOTÕES DE RÁDIO (TYPE="RADIO")

Em um grupo de botões de rádio (ex.: escolher entre PAC, SEDEX ou Retirada), todos os inputs devem ter o mesmo name (para que apenas um possa ser marcado por vez), mas cada um deve ter seu próprio id exclusivo para vincular ao seu respectivo <label>.

4. Desafio interativo e quadro-síntese #

Resolva as três rodadas interativas abaixo para consolidar os conceitos centrais deste caderno antes de abrir os arquivos práticos:

Conceito-chaveRegra prática na Vitrine Lojas Blue
Estrutura de Tabela<caption> (título) + <thead> (cabeçalho) + <tbody> (corpo) + <tfoot> (rodapé totalizador).
Botões dentro de <form>Sempre explicite type="submit" (envia), type="reset" (limpa) ou type="button" (ação JS sem enviar).
